Q1 How does the Emergency Tele-Triage feature protect patients in acute clinical risk?

Ans: When a patient triggers the 1-click SOS button on their app, an urgent encrypted notification containing priority medical telemetry (heart rate, SpO2, blood pressure, ECG arrhythmia status, GPS) is dispatched to their designated doctor via WebSockets and Push Protocol in < 380 ms. The doctor can immediately launch a secure WebRTC video/voice call to review real-time vitals and prescribe immediate emergency precautions.

Q2 What happens when an unauthorized user attempts to modify or tamper with a patient's record?

Ans: The smart contract validates cryptographic ownership via ECDSA signatures using Audit(H_CID, σ) = 1{VerifySig(pk_patient, H_CID, σ)}. An unauthorized modification attempt automatically triggers a transaction revert and an on-chain UnauthorizedTamperAttempt event is emitted (costing <= 42,500 gas). The automated daemon intercepts this log, extracts attacker proxy IP details via GeoIP2, and instantly dispatches a dual alert to BOTH patient and doctor for non-repudiable legal attribution.

Q3 Why is Proxy Re-Encryption essential for sharing medical records between patient and doctor?

Ans: In traditional systems, sharing encrypted data requires either sharing the master private key or decrypting files on a central cloud server (creating single point of failure). Proxy Re-Encryption (BBS98) allows an untrusted proxy server to transform patient-encrypted ciphertext C_A = (g^{r * sk_A}, m * g^r) into doctor-encrypted ciphertext C_B = (g^{r * sk_B}, m * g^r) using re-encryption key rk_{A->B} = (sk_B / sk_A) mod q, without the proxy ever learning or exposing the plaintext medical record.
